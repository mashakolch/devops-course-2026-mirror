## 1. Почему ветвление в Git «дешёвое», а в SVN — «дорогое»?

**Git:** ветка — это указатель на коммит (файл ~41 байт в `.git/refs/`).
Создание и переключение — мгновенно, локально, без копирования файлов.

**SVN:** ветка — копия директории в репозитории (`svn copy`). Операция
идёт через сервер, создаёт новую ревизию, а `svn switch` перезаписывает
всю рабочую копию.

## 2. Можно ли в SVN коммитить без интернета?

**Нет.** SVN централизован: вся история — на сервере, локально только
рабочая копия. `svn commit` отправляет изменения на сервер и получает
номер ревизии — без сети невозможно.

**В Git** можно: репозиторий целиком лежит в `.git`, `git commit`
работает офлайн. Сеть нужна только для `push`/`fetch`.

## 3. Когда SVN предпочтительнее Git?

- Большие бинарные файлы (геймдев, CAD, видео).
- Частичный checkout больших репозиториев.
- Права доступа по путям (`authz`) из коробки.
- Централизованный аудит и бэкапы (банки, госсектор).
- Простой линейный workflow для не-программистов.
- Legacy-инфраструктура: миграция дороже, чем остаться.
- Глобальный номер ревизии на весь репозиторий.
